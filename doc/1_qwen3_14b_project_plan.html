📌 项目定位

本项目旨在利用摩尔线程 MTT S4000 (48GB) 国产 GPU 服务器，完成 Qwen3-14B 大语言模型的量化压缩 → 微调适配 → 高效推理 → API 服务化 → 本地 Agent 集成的全链路部署，形成一个完整的、可展示的 AI 工程化项目。

🎯 核心目标

学习路线目标

  • 环境搭建：掌握国产 MUSA 生态的环境配置、驱动安装、依赖管理
  • 模型量化：理解并实践 INT8/INT4 量化（GGUF/AWQ/GPTQ），对比精度与速度
  • 微调训练：掌握 LoRA/QLoRA 高效微调方法，完成领域适配
  • 推理部署：搭建高吞吐推理服务（vLLM-MUSA / SGLang / llama.cpp），支持并发
  • API 服务化：封装 OpenAI 兼容接口，实现远程调用
  • Agent 集成：本地 Agent 框架对接远程模型，实现工具调用与多轮对话

📦 最终交付物

  • 可运行的 Qwen3-14B 量化推理服务（OpenAI 兼容 API）
  • 微调后的领域适配模型权重（LoRA 适配器 + 合并模型）
  • 本地 Agent 调用 Demo（Python / LangChain / 自研框架）
  • 完整的实验记录文档（量化对比表、微调日志、性能基准）

⚠️ 关键限制与应对

🔴 生态成熟度 高风险

MUSA 生态仍落后于 CUDA，部分库（如 Triton 内核）可能不兼容。建议优先使用官方预编译 wheel 和容器镜像。

🟡 量化工具链 中风险

AWQ/GPTQ 的 CUDA/Triton 内核在 MUSA 上可能不可用。llama.cpp MUSA 后端 + GGUF 是目前最稳妥的量化推理路径。

🟢 显存充足 低风险

48GB 显存对 14B 模型非常宽裕：FP16 全量约 28GB，INT8 约 14-16GB，INT4 约 8-10GB，均可在单卡完成。

📊 显存需求估算

精度模式 权重显存 KV Cache (4K ctx) 总计 可行性
FP16 / BF16 ~28 GB ~4-6 GB ~34 GB ✅ 单卡可行
INT8 ~14 GB ~4-6 GB ~20 GB ✅ 非常宽裕
INT4 (GGUF Q4_K_M) ~8.5 GB ~4-6 GB ~14 GB ✅ 可开大上下文
LoRA 微调 (QLoRA) ~8.5 GB (4bit base) ~6-8 GB (梯度等) ~18 GB ✅ 单卡可微调

Phase 1：基础环境搭建

目标：服务器可正常识别 GPU，MUSA 开发环境就绪。


核心任务：

  • 安装 MUSA 驱动（建议 ≥ 4.3.2）和 MUSA Toolkit
  • 配置 BIOS：开启 Above 4G Decoding / Resizable BAR / IOMMU
  • 验证 mthreads-gmi / musa-smi 正常输出
  • 安装 torch_musa（预编译 wheel，注意 NumPy 版本锁定）
  • 配置 LD_LIBRARY_PATH 等环境变量
  • 运行 deviceQuery 确认 GPU 可用

验收标准：

  • ✅ musa-smi 显示 GPU 状态正常
  • ✅ import torch_musa; torch_musa.is_available() == True
  • ✅ 简单矩阵运算可在 GPU 上执行
# 环境验证脚本
import torch
import torch_musa

print(f"MUSA available: {torch_musa.is_available()}")
print(f"Device count: {torch_musa.device_count()}")

x = torch.randn(1000, 1000).to("musa")
y = torch.randn(1000, 1000).to("musa")
z = x @ y
print(f"Matmul result shape: {z.shape}")

Phase 2：模型量化与推理部署

目标：Qwen3-14B 在 S4000 上成功运行推理，并通过 API 对外服务。


方案 A：llama.cpp + MUSA（推荐，最稳）

  • 下载 Qwen3-14B GGUF 量化模型（Q4_K_M / Q5_K_M / Q8_0）
  • 使用编译好的 llama.cpp MUSA 后端
  • 启动 llama-server 提供 OpenAI 兼容 API
  • 测试不同量化等级的显存占用和生成速度

方案 B：torch_musa + HuggingFace（适合微调衔接）

  • 直接加载 SafeTensors 权重（FP16）
  • 使用 transformers 的 device_map 部署
  • 封装 FastAPI 服务层

量化方案对比实验：

量化方式 工具链 显存占用 速度 MUSA 兼容性
FP16 (无量化) torch_musa / vLLM ~28 GB 基准 ✅ 最佳
INT8 torch_musa + bitsandbytes ~15 GB 略快 ⚠️ 需验证
GGUF Q4_K_M llama.cpp MUSA ~10 GB 快 ✅ 稳定
GGUF Q5_K_M llama.cpp MUSA ~12 GB 较快 ✅ 稳定

Phase 3：模型微调（LoRA / QLoRA）

目标：使用 LoRA/QLoRA 对 Qwen3-14B 进行领域微调，掌握高效微调全流程。


学习路径：

  • 理解 LoRA 原理（低秩矩阵分解、可训练参数占比）
  • 准备指令微调数据集（Alpaca 格式 / ShareGPT 格式）
  • 使用 PEFT 库进行 LoRA 配置
  • 在 MUSA 上运行微调训练
  • 合并 LoRA 权重到基础模型
  • 评估微调前后效果差异

微调配置示例：

from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

# LoRA 配置
lora_config = LoraConfig(
  r=16, # 秩
  lora_alpha=32, # 缩放因子
  target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
  lora_dropout=0.05,
  bias="none",
  task_type="CAUSAL_LM"
)

# 加载基础模型（4bit 量化以节省显存）
model = AutoModelForCausalLM.from_pretrained(
  "Qwen/Qwen3-14B",
  load_in_4bit=True,
  device_map="auto",
  trust_remote_code=True
)

# 应用 LoRA
model = get_peft_model(model, lora_config)
model.print_trainable_parameters() # 通常 < 1%

数据集推荐：

数据集 规模 用途 获取方式

训练技巧：

  • 使用梯度累积（gradient_accumulation_steps）模拟大 batch
  • 学习率建议 1e-4 ~ 3e-4（LoRA 通常比全量微调大 10x）
  • 使用余弦退火或线性衰减学习率调度
  • 开启 Flash Attention（如 MUSA 支持）加速训练
  • 定期保存 checkpoint，记录 loss 曲线

# FastAPI 封装示例（自研服务层）
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import httpx
import os

app = FastAPI(title="Qwen3-14B API")

LLAMA_SERVER = "http://localhost:8000"
API_KEY = os.getenv("API_KEY", "your-secret-key")

class ChatRequest(BaseModel):
  messages: list
  temperature: float = 0.7
  max_tokens: int = 2048

@app.post("/v1/chat/completions")
async def chat(req: ChatRequest, x_api_key: str = Header(None)):
  if x_api_key != API_KEY:
    raise HTTPException(401, "Unauthorized")
  async with httpx.AsyncClient() as client:
    resp = await client.post(
      f"{LLAMA_SERVER}/v1/chat/completions",
      json=req.dict()
    )
    return resp.json()

风险预案与踩坑指南

提前识别项目中的潜在风险，并给出具体解决方案。

🔴 MUSA 版本兼容性问题

现象：torch_musa 与 PyTorch 版本不匹配，import 报错。

方案：严格使用官方预编译 wheel，锁定 NumPy < 2.0，确认 LD_LIBRARY_PATH 指向正确版本目录。

🔴 AWQ/GPTQ 在 MUSA 不可用

现象：依赖 CUDA/Triton 内核的量化方法无法运行。

方案：优先使用 GGUF 量化（llama.cpp MUSA 后端），这是目前最稳定的路径。FP16 全精度也可作为 fallback。

🟡 网络带宽限制推理速度

现象：远程调用时网络延迟高，流式输出卡顿。

方案：使用 Tailscale/ZeroTier 组网降低延迟；服务端开启流式输出；考虑在服务器端做结果缓存。

🟡 微调时显存不足

现象：即使 48GB 显存，长序列微调仍可能 OOM。

方案：使用 QLoRA（4bit base）+ 梯度检查点 + 梯度累积；减小 max_seq_length 到 2048；使用 DeepSpeed ZeRO-2。

🟢 驱动升级导致环境破坏

现象：系统更新后 MUSA 驱动失效。

方案：锁定内核版本，禁止自动更新；定期备份环境镜像（Docker / 系统快照）。

🟢 模型下载慢/失败

现象：HuggingFace 模型下载超时。

方案：使用 hf-mirror 镜像站；提前下载 GGUF 文件到本地；使用 aria2c 多线程下载。

📋 常见问题速查表

问题 可能原因 解决方案
