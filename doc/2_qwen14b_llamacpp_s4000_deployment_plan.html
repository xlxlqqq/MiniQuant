从“裸的 S4000 云服务器”到 Qwen 14B 第一次 GPU 推理

这不是单纯的部署教程，而是一条可形成简历项目的 LLM 推理工程学习路线。目标是亲自完成：GPU/CUDA 环境检查 → llama.cpp CUDA 编译 → Qwen 14B 选择 → 模型下载 → HF 转 GGUF → F16 基线 → 量化 → GPU Offload → Server → Benchmark。

01 · 项目目标

阶段 1环境可用
识别 GPU / Driver / CUDA / GCC
阶段 2源码编译
自己编译 CUDA 版 llama.cpp
阶段 3模型闭环
HF → GGUF → GPU 推理
阶段 4量化工程
Q8/Q6/Q5/Q4 对比
核心原则：不要一开始下载别人已经量化好的 Q4 模型。先建立 F16 基线，再自己量化。这样才能真正学习模型格式、量化、显存、GPU Offload 和推理性能之间的关系。

02 · 总体路线

裸 S4000 云服务器 ↓ nvidia-smi / nvcc / gcc / cmake ↓ CUDA Backend 检查 ↓ 编译 llama.cpp ↓ 验证 llama-cli / llama-bench / llama-quantize ↓ 选择合适的 Qwen 14B Instruct 模型 ↓ HF 权重下载 ↓ HF → GGUF F16/BF16 ↓ 第一次 GPU 推理 ↓ 记录 Baseline：显存 / TTFT / Prompt TPS / Decode TPS ↓ Q8_0 / Q6_K / Q5_K_M / Q4_K_M ↓ GPU Offload + Flash Attention + KV Cache ↓ Benchmark ↓ llama-server OpenAI-compatible API ↓ 形成可展示的 LLM Inference 项目

04 · CUDA / 编译器检查

这一阶段的目的不是“安装软件”，而是建立一个可解释的编译环境。

4.1 检查 CUDA 路径

echo $CUDA_HOME
echo $PATH
echo $LD_LIBRARY_PATH
ls -l /usr/local/ | grep cuda
ls -l /usr/local/cuda/bin/nvcc 2>/dev/null

4.2 如果 CUDA_HOME 未设置

export CUDA_HOME=/usr/local/cuda
export PATH=$CUDA_HOME/bin:$PATH
export LD_LIBRARY_PATH=$CUDA_HOME/lib64:$LD_LIBRARY_PATH

不要机械执行。先通过 ls 确认 CUDA 的真实安装路径。

4.3 编译器验证

echo 'int main(){return 0;}' > /tmp/test.cpp
g++ /tmp/test.cpp -o /tmp/test
/tmp/test
echo $?
验收：最后输出 0，说明基础 C++ 编译链正常。

05 · 编译 llama.cpp CUDA 版本

5.1 获取源码

cd ~
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp

建议固定一个 Git commit/tag，并记录到 README，避免未来版本变化影响实验复现。

5.2 CUDA 构建

cmake -B build \
  -DGGML_CUDA=ON \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build \
  --config Release \
  -j$(nproc)

5.3 找到核心程序

find build -type f \( \
  -name "llama-cli" -o \
  -name "llama-server" -o \
  -name "llama-bench" -o \
  -name "llama-quantize" \
\) -print

5.4 检查 CUDA 编译结果

./build/bin/llama-cli --help
./build/bin/llama-server --help
./build/bin/llama-bench --help
./build/bin/llama-quantize --help
路径说明：不同 llama.cpp 版本的可执行文件布局可能变化。如果 build/bin 下没有目标文件，不要自行猜路径，使用 find 查找。

06 · Qwen 14B 版本选择

第一版建议选择 Qwen 14B Instruct 类模型，而不是 Base 模型。你的项目最终要展示对话式推理，因此 Instruct 更容易做 Demo 和 API 服务。

选择建议原因
Qwen 14B Base不作为第一选择更适合继续预训练/研究
Qwen 14B Instruct推荐适合 Chat / API / Agent 场景
官方 GGUF可作为后期对照方便验证自己的转换结果
第三方 Q4 GGUF不要作为第一步会跳过转换与量化学习过程
版本策略：优先选 Qwen 官方 Hugging Face 上与你计划使用的 llama.cpp/transformers 支持情况匹配的 14B Instruct 模型。具体仓库名不要在没有确认当前版本的情况下硬编码。

07 · 模型下载

7.1 建议目录

mkdir -p ~/qwen14b-project/models/hf

验收

find ~/qwen14b-project/models/hf -maxdepth 2 -type f | head -30

08 · Hugging Face → GGUF

这是第一次真正接触“模型部署格式转换”的地方。核心理解：HF 模型权重不是 llama.cpp 最终直接使用的 GGUF 文件，需要经过转换。

8.1 找转换脚本

cd ~/llama.cpp
find . -name "convert-hf-to-gguf.py" -print

8.2 转换

python3 convert_hf_to_gguf.py \
  ~/qwen14b-project/models/hf \
  --outfile ~/qwen14b-project/models/gguf/qwen14b-f16.gguf \
  --outtype f16

实际脚本名和参数以当前 llama.cpp 版本的 --help 为准。先运行：python3 <转换脚本> --help。

8.3 检查 GGUF

ls -lh ~/qwen14b-project/models/gguf/
./build/bin/llama-cli --help
关键验收：成功得到 qwen14b-f16.gguf，文件大小合理，且 llama.cpp 能识别模型元信息。

09 · 第一次 F16 GPU 推理

9.1 先检查模型

./build/bin/llama-cli \
  -m ~/qwen14b-project/models/gguf/qwen14b-f16.gguf \
  --help

9.2 第一次推理

./build/bin/llama-cli \
  -m ~/qwen14b-project/models/gguf/qwen14b-f16.gguf \
  -ngl 99 \
  -c 2048 \
  -p "请介绍一下大语言模型量化的基本原理。"

如果 F16 无法完整放入 GPU，不要认为项目失败。记录显存情况，然后进入量化阶段；这本身就是一个实验结果。

9.3 同时观察 GPU

watch -n 1 nvidia-smi

10 · 量化路线

完成 F16 Baseline 后再量化。建议至少比较 Q8_0、Q6_K、Q5_K_M、Q4_K_M。

10.1 量化命令模板

./build/bin/llama-quantize \
  ~/qwen14b-project/models/gguf/qwen14b-f16.gguf \
  ~/qwen14b-project/models/gguf/qwen14b-q4_k_m.gguf \
  Q4_K_M

其他精度只替换最后一个量化类型和输出文件名。

10.2 建议实验矩阵

版本目的
F16质量/显存基线
Q8_0接近高精度的量化对照
Q6_K精度与压缩的中间点
Q5_K_M推荐重点观察
Q4_K_M高压缩/低显存重点观察

10.3 量化后必须回答的三个问题

  1. 模型文件减少了多少？
  2. GPU VRAM 减少了多少？
  3. Decode TPS 和回答质量发生了什么变化？
学习重点：量化不是“越低越好”。真正的工程问题是找到 显存、速度、质量 三者的合理 Pareto 点。

12 · llama-server：从 CLI 到 API

完成单机 CLI 后，再进入服务化。llama.cpp 提供 llama-server，可作为 OpenAI-compatible HTTP 服务使用。

12.1 启动模板

./build/bin/llama-server \
  -m ~/qwen14b-project/models/gguf/qwen14b-q4_k_m.gguf \
  -ngl 99 \
  -c 4096 \
  --host 0.0.0.0 \
  --port 8080

参数以当前版本 llama-server --help 为准。

12.2 验收

curl http://127.0.0.1:8080/health

16 · 简历表达

项目名称：基于 llama.cpp 的 Qwen 14B 大语言模型量化与高性能推理部署系统

项目描述：基于 CUDA、GGUF 与 llama.cpp 搭建 Qwen 14B 本地推理系统，完成 Hugging Face 权重到 GGUF 的格式转换及 Q8/Q6/Q5/Q4 多档量化，研究 GPU Offload、KV Cache、Flash Attention 等推理优化机制，并构建统一 Benchmark 对显存占用、TTFT、Prefill/Decode 吞吐及模型质量进行评测，最终通过 llama-server 提供 OpenAI-compatible 推理 API。

面试核心：为什么量化？为什么 GGUF？为什么 GPU Offload？KV Cache 占多少显存？Prefill 和 Decode 有什么区别？Q4/Q5/Q8 如何选择？如何定位推理瓶颈？

简历里不要只写“部署 Qwen 14B”。真正值得写的是：你做了什么实验、量化前后发生了什么、为什么这么设计、性能提升/成本下降多少。
